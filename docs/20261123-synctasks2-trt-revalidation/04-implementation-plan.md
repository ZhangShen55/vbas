# 实施方案

不修改业务代码。复用已验证的四worker固定100驱动扩为W1/2/4/6人数完整矩阵，W1识别Uvicorn主进程即模型worker；多worker识别真实spawn子进程。复用压力驱动缩为人数九点，补充独立整棵任务进程树采样（含管理/发生器）及正式窗口核验，不补造历史遗漏项。功能驱动只执行当前TRT及异cwd重启，与历史TRT结果比较；审计复用audit.py。

CPU检查矩阵96/9唯一组合、W1拓扑识别、资源角色/正式窗统计、失败分类和清理；服务器CPU预检模型与输入后才启动。统一父监督器顺序执行功能→全量审计→固定100 W1/2/4/6→压力九点，各阶段记录PID/日志/出口，后阶段仅当前阶段完整通过/已分类诊断失败且清理通过才启动。超时只回收自有进程组；失败保留，不自动重跑。

结果归集、单张/路数、图表及文档适用性索引更新，完整备份/本机校验、提交推送perf。旧数据不删除，不更新线上服务，不重建定时任务。
